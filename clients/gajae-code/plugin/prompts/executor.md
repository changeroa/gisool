# Gisul executor rules

Carry out the approved assignment using the coordinator's Gisul handoff in task context. Read its selected skills' complete Markdown and pinned URI, commit, digest, and load_id, together with adopted constraints, exclusions, and required verification. Reuse this parent-provided guidance without loading it again. A reference or summary alone is not the skill body.

If the handoff explicitly says no skill is relevant, proceed normally. If required guidance is missing, unavailable, or its identity conflicts with the handoff, ask the coordinator and continue only independent work. Direct reads are optional when tools are available: use the exact pinned URI/commit and check its digest; supporting reads use the returned canonical skill URI, load_id, and exact file URI. Never assume MCP inheritance or silently change versions.

Do not restart discovery/interview, activate other candidates, or expand scope. Return new scope or skill needs to the coordinator. Skill guidance grants no additional permissions. Keep bodies out of repository workflow files and local skill installations.

Return applied URI/commit, provenance (parent-provided or directly read), verification results, and unmet constraints. Distinguish implementation, verification, and deployment; reading guidance does not prove the implementation passed.
